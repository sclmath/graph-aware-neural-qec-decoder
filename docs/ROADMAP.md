## 2. 当前限制与证据缺口

### 2.1 统计功效

- OSD-CS 的表面码 d=3 研究仍为单 seed。
- 表面码 d=3 → d=5 的 code-capacity 迁移仍为单 seed。
- repetition d=5 的先验强度尚未做多种子验证。
- 小差异结论应先补到至少 3 seeds，再进入正式报告。

### 2.2 码族与规模

- 结构化量子 LDPC（非 HGP）尚未实现，当前 HGP 只覆盖两个小型码。
- d=9 位于当前 BP 的失能区，收敛率接近 0，未纳入第一阶段。
- HGP 跨尺寸迁移在 3 个模型 seed 上均值为 +2.0% ± 7.1%，当前不支持稳健收益。
- 线路级 HGP 与更大码族的系统扫描仍缺失。

### 2.3 模型与算法

- GNN 推理在 d=7 上仍为数十毫秒/shot 量级，尚未达到低延迟部署目标。
- 当前混合路径主要是学习先验或候选基，尚未实现端到端可微 BP。
- 时序编码器、syndrome history 建模与跨轮次关联尚未进入实验。
- OSD-CS 相对 `bp_gnn` 的额外收益只在部分低噪声点出现方向性证据，需要更强候选排序目标。
- 现有跨噪声率评测仍把 p 作为输入特征，不等同于真零样本迁移。

### 2.4 工程与平台

- GPU 延迟、吞吐、显存和量化收益尚未测量。
- 当前延迟数字来自单一 CPU 环境，不能直接外推到其他硬件。
- 未实现流式、并行时间窗、近实时门控或硬件部署路径。

## 3. 后续研究方向

按建议优先级排列：

1. **统计补强**：把单 seed 的 OSD-CS、迁移和先验强度结论补到 3 seeds；统一报告 seed 间散布与配对区间。
2. **GPU 工程评测**：把活动集合切片和边聚合迁移到 GPU 友好的张量/稀疏操作，测量延迟、吞吐、显存与量化后的精度变化。
3. **候选排序与 learning-to-rank**：直接用 LER 相关目标学习 OSD 候选顺序，与 OSD-CS、`bp_gnn` 做多种子配对比较。
4. **真零样本与课程训练**：移除输入中的物理噪声率 p，研究多噪声率课程、分布外检测与校准。
5. **HGP 扩展**：增加不同基矩阵、尺寸和逻辑维度的码族，验证跨尺寸与跨族迁移。
6. **结构化量子 LDPC**：实现非 HGP 的 qLDPC 构造与 BP+OSD 接入，这是当前码族覆盖中最大的缺口。
7. **d=9 与更大码距**：先解决 BP 收敛和内存瓶颈，再扩大 shots 与 seed 数。
8. **精确机制映射与匹配图优化**：补齐原始/分解机制对应，避免逐 shot 重建匹配图。
9. **时序与可微推断**：探索轻量时序编码器、可学习 BP 偏置和端到端训练，但需先建立可靠的延迟与精度基线。

## 4. 算力与平台建议

第一阶段已证明：小到中等码距的 GNN 训练和 BP 评测可在 CPU 上完成，但 d=7 训练和评测以小时计，d=9 和大规模多种子扫描更适合 GPU 或混合 CPU/GPU 流程。

若扩展到大码距、时序模型和完整消融，建议至少具备：

- 16 核以上 CPU
- 64 GB 以上系统内存
- 24 GB 以上显存的 NVIDIA GPU
- 1 TB 以上本地 NVMe，并配合独立数据盘或对象存储

这只是后续工作的量级建议，不是当前仓库的复现要求。采购或云部署前应先运行 profiling，确认显存、内存和 OSD 处理分别是否为真正瓶颈。
