## 1. 动机：三条独立证据都指向「候选集」

| 证据 | 结论 |
|---|---|
| M2 | 把学习 logits 当作 OSD-0 的候选基排序（`bp_gnn_osd_learned_order`）无可复现收益 |
| M3 | OSD-0 回退在 d=3 上 67 修好 / 88 弄坏（p=0.092），不存在「只救不伤」的触发阈值，只有一条陡峭的 LER-一致性 Pareto 前沿 |
| M5 | 把学习后验接进 MWPM 边权重没有 LER 收益（码容量 455 → 最好 451） |

共同解释：**逐机制边际回答「每个机制是否发生」，而候选基选择需要「哪些位构成可解的基」。** 本项把学习目标从边际换成候选集质量——先用最经典的候选集机制（OSD-λ / combination sweep）验证这条路是否成立。

## 2. 方法：OSD-CS(λ)

`bp → OSD` 的后处理路径扩展为：

1. 按 `|posterior LLR|` 降序排列列，Gaussian elimination 选出 pivot 基（与 OSD-0 相同）；
2. **组合扫描**：取 λ 个**最不可靠的非 pivot 列**，枚举其全部 2^λ 个子集（Gray 码，增量维护 pivot 位与软权重），取 `Σ_i |posterior_llr_i| · c_i` 最小的候选。

`λ = 0` 退化为 OSD-0（与旧实现逐位一致，见单测）。λ 在配置里由 `decoder.osd_combination_sweep` 给出；注册的新解码器为 `bp_osd_cs`（DEM 先验）、`bp_gnn_osd_cs`（学习先验）、`bp_gnn_osd_cs_learned_order`（学习先验 + 学习排序）。

### 3.3 旋转表面码 d=7，线路级 p = 0.003 / 0.005 / 0.008（每个 p 3 份独立测试集 × 1024 shots）

d=7 上 BP 已接近失效（收敛率 0.118-0.121、平均迭代 28.9/32），是检验「候选集杠杆」最强的场景。为控制成本这里用 1024-shot 探针，**每个噪声率 3 份独立测试集**（`--seed-offset 0/10/20`，共用同一 checkpoint；汇总 `results/t8/D7_MULTISEED.md`）：

| d=7 p | mwpm | bp | bp_gnn | OSD-0<br>`bp_gnn_osd_cs0` | **OSD-CS(4)**<br>`bp_gnn_osd_cs4` | Δ(cs4 vs gnn) | Δ(cs4 vs OSD-0) | Δ(cs4 vs bp) |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.003 | 0.00130 | 0.16276 | 0.08854 | 0.09993 | **0.05762** | **−34.9%**（z=−5.39） | −42.3%（z=−9.48） | **−64.6%** |
| 0.005 | 0.01042 | 0.24219 | 0.17741 | 0.20931 | **0.15690** | **−11.6%**（z=−2.67） | −25.0%（z=−9.22） | **−35.2%** |
| 0.008 | 0.05371 | 0.34961 | 0.30241 | 0.36035 | 0.29655 | −1.9%（n.s.） | −17.7%（z=−9.10） | −15.2% |

三条读数：

1. **OSD-0 在高噪声率上已显著有害**：`bp_gnn_osd_cs0` 比 `bp_gnn` 差 +12.9% / +18.0% / +19.2%（z=+1.81 / +4.09 / +6.19）——把 3.1/3.2 的负结果推到了 d=7。
2. **OSD-CS(4) 在三个点上都把 OSD-0 的伤害翻成收益，且证据很强**：相对 OSD-0 为 −42.3% / −25.0% / −17.7%，z=−9.5 / −9.2 / −9.1。
3. **但收益随噪声率迅速衰减**（相对 `bp_gnn` −34.9% → −11.6% → −1.9%），与 FINAL_REPORT 4.6 第 2 条「噪声率轴」规律一致：噪声率越高，机制判别本身越糊，候选集能救回的份额越小。

**口径**：三份测试集只换测试集种子、共用同一份模型权重，因此压的是 **LER 估计**误差而不是模型种子方差；同 p 的多份测试集相互独立，逐 shot 错误可直接汇总，故用 pooled 标准误与 pooled McNemar。

## 4. 关键结论

1. **OSD 回退从「有害」变成「显著有益」。** 两个配置上 OSD-0 都让 LER 变差（repetition z=-1.73、表面码 z=-3.19），而 OSD-CS(4) 让 repetition 从 0.00943 降到 0.00754（-20%），OSD-CS(8) 让表面码从 0.04007 降到 0.02505（-37%）。这正是 T8 要提供的**正面出口**。
2. **收益来自未收敛 shot。** 表面码上 1521/32768 个 shot 未收敛：其中 `bp_gnn` 764 错，OSD-0 把它推到 955（弄坏），OSD-CS(8) 压到 **259**（MWPM 参考 209）。也就是说 OSD-CS 在最有价值的子集上把 OSD-0 的伤害反转成了 3× 的改进。
3. **候选集选对之后，逐机制边际信息量下降。** repetition 上 DEM 先验与学习先验在 λ=4 上打平（247 vs 249，McNemar p=0.53）；这与 M2/M5 的「边际用不上」系列结论一致，也给它们提供了正面解释。
4. **但在 BP 更弱的表面上，学习先验仍有增量。** 表面码上 `bp_osd_cs8` 821 → `bp_gnn_osd_cs8` **627**（-24%，z=8.07）。规律与 M4 一致：**BP 越弱，学习先验越有用**。
5. **`bp_gnn_osd_cs8` 已接近 MWPM**：0.01913 vs 0.01694（差 +13%），而 `bp` 差 +137%。这是本项目第一个在表面码上把 BP 系解码器拉到 MWPM 附近的配置。

## 5. 成本（CPU 实测，强制每 shot 都跑 OSD）

| 配置 | λ=0 | λ=2 | λ=4 | λ=6 | λ=8 |
|---|---:|---:|---:|---:|---:|
| repetition d=3 电路级 | 149 µs/shot | 189 | 304 | 469 | 1087 |
| 表面码 d=3 电路级 | 1323 µs/shot | 1615 | 1548 | 1852 | 2432 |

复杂度是 2^λ（实现里把 λ 上限压到 12）。实际运行 OSD 只在未收敛 shot 上触发：repetition d=3 约 1%（开销可忽略），表面码 d=3 约 60%（λ=8 使端到端约 2-3× `bp`）。**推荐工作点 λ=4**：表面码上 0.02759 vs λ=8 的 0.02505，用 1.6× 的 OSD 开销换 10% 的 LER——存在可用的 λ-pareto 前沿。

## 6. 顺带完成 T9 的一部分：候选规模（top-k）消融

λ ∈ {0, 2, 4, 6, 8} 的扫描就是 README 7.2 中「不同 top-k 候选规模」的消融：

- 表面码上 **单调**（0.04315 → 0.03186 → 0.02759 → 0.02545 → 0.02505）；
- repetition 上**非单调**，λ=4 最优（331 → 285 → 247 → 281 → 280）。

非单调说明「最小化 `Σ|posterior LLR|`」这个目标只是 LER 的代理：λ 变大时搜索空间变大、目标值单调不增，但代理与真实 LER 之间存在错位（BP 未收敛时 posterior 本身不可靠）。这是后续 learning-to-rank 的直接动机。

## 7. 局限与后续

- 本项只做了**候选集机制**（OSD-CS），没有做**数据驱动的候选排序**（learning-to-rank）。后者列为 P2 强化项。
- OSD-CS 的目标函数仍用 BP posterior；第 6 节说明它是可改进的代理。
- **d=7 已补测**（第 3.3 节：三个噪声率、每个 p 3 份独立测试集，OSD-CS 相对 `bp_gnn` 为 −34.9% / −11.6% / −1.9%）；**d=5 与 HGP 仍未复测**（算力受限）。注意 d=7 的结果说明「BP 越弱收益越大」在**噪声率轴**上并不成立：p 越高收益反而越小，两个轴要分开说。
- OSD-CS 的实现是逐 shot 的 Python 循环 + numpy 小算子；若要走低延迟路线需要批量化和位运算重写。
